# Решение: legacy-интерфейс на Astro

- Дата: 2026-09-07
- Статус: release candidate, проверено в репозитории
- Область: `shch.one`, репозиторий `shch-space`

## Причина

Владелец не принял визуальное направление первого Astro-релиза и запросил
возврат лаконичной версии сайта, опубликованной до редизайна.

## Проверенный эталон

- Визуальный и структурный baseline: commit
  `71fa6497998f852238ed08ae65b416408b751caa`.
- Последний опубликованный Astro-релиз до восстановления:
  `b1b9b2c6e52be6a6f199005708545bb2247e4c48`.
- До изменения production отвечал через GitHub Pages.

## Решение

- Оставить Astro 7, Content Layer, Obsidian-снимок, статические URL, canonical и
  аналитику.
- Перенести в Astro визуальный язык legacy-сайта: IBM Plex Mono, белый фон,
  полупрозрачную оранжевую строку, старый знак, простые списки и двухколоночные
  страницы с медиа справа.
- Не возвращать Gatsby, React, GraphQL, Google Sheets и старые зависимости.
- Сохранить архивный статус записи `website-story`: страница не публикуется.
- Оставить существующие маршруты блокнота, проектов, алиаса и магазина.

## Проверка кандидата

- `pnpm check`: 0 ошибок, предупреждений и замечаний.
- `pnpm build`: 11 статических страниц и 29 оптимизированных изображений.
- Локальные публичные маршруты отвечают `200`; `/notes/website-story/`
  отвечает `404`.
- Полный dependency audit и production read-back выполняются перед завершением
  релиза.

## Откат

Если восстановленный интерфейс нужно снять, повторно опубликовать Astro-релиз
`b1b9b2c6e52be6a6f199005708545bb2247e4c48`. Возврат к Gatsby для этого не
требуется.

## Принятие

Техническая проверка не равна визуальному принятию. После публикации владелец
отдельно подтверждает, что legacy-интерфейс восстановлен в нужной степени.
