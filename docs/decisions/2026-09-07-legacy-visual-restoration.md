# Решение: legacy-интерфейс на Astro

- Дата: 2026-09-07
- Статус: опубликовано и проверено в runtime
- Область: `shch.one`, репозиторий `shch-space`

## Причина

Владелец не принял визуальное направление первого Astro-релиза и запросил
возврат лаконичной версии сайта, опубликованной до редизайна.

## Проверенный эталон

- Визуальный и структурный baseline: commit
  `71fa6497998f852238ed08ae65b416408b751caa`.
- Последний опубликованный Astro-релиз до восстановления:
  `b1b9b2c6e52be6a6f199005708545bb2247e4c48`.
- До изменения production отвечал через GitHub Pages.

## Решение

- Оставить Astro 7, Content Layer, Obsidian-снимок, статические URL, canonical и
  аналитику.
- Перенести в Astro визуальный язык legacy-сайта: IBM Plex Mono, белый фон,
  полупрозрачную оранжевую строку, старый знак, простые списки и двухколоночные
  страницы с медиа справа.
- Не возвращать Gatsby, React, GraphQL, Google Sheets и старые зависимости.
- Сохранить архивный статус записи `website-story`: страница не публикуется.
- Оставить существующие маршруты блокнота, проектов, алиаса и магазина.

## Проверка кандидата

- `pnpm check`: 0 ошибок, предупреждений и замечаний.
- `pnpm build`: 11 статических страниц и 29 оптимизированных изображений.
- Локальные публичные маршруты отвечают `200`; `/notes/website-story/`
  отвечает `404`.
- Полный dependency audit: известных уязвимостей нет.

## Результат релиза

- Release commit:
  `ddb749dbe85874786b85cc80992f3543491166fa`.
- GitHub Pages workflow `34144996687` завершился успешно.
- 46 из 46 публичных файлов побайтно совпали с локальным `dist/`.
- Главная, блокнот, проектные страницы, alias проекта и магазин отвечают `200`.
- `/notes/website-story/` отвечает `404`.

## Откат

Если восстановленный интерфейс нужно снять, повторно опубликовать Astro-релиз
`b1b9b2c6e52be6a6f199005708545bb2247e4c48`. Возврат к Gatsby для этого не
требуется.

## Принятие

Техническая проверка не равна визуальному принятию. Владелец отдельно
подтверждает, что legacy-интерфейс восстановлен в нужной степени.

## Корректировка мобильных стилей

После публикации владелец указал на расхождение размера заголовков и лишнее
пустое место на главной в мобильной версии. Проверка исходного legacy CSS
подтвердила размер `text-5xl`, то есть `3rem`; при переносе мобильное правило
ошибочно уменьшало его до `2.75rem`.

Корректирующий release candidate:

- возвращает заголовкам единый размер `3rem` и исходный нижний отступ;
- уменьшает занимаемую логотипом высоту только на мобильных;
- убирает мобильные фиксированные высоты у заголовков секций главной;
- убирает `min-height: 100vh` у списка проектов на мобильных;
- не меняет desktop-композицию и страницы проектов.
