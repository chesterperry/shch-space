# Решение: полная миграция shch.one на Astro

- Дата: 2026-09-04
- Статус: реализовано локально, не опубликовано
- Область: репозиторий `shch-space`

> Уточнение 2026-09-07: предположение о production-публикации в S3 оказалось
> неверным. Фактический хостинг — GitHub Pages; актуальное решение описано в
> `2026-09-07-github-pages-release.md`.

## Контекст

Предыдущий сайт был статической сборкой на Gatsby с React-компонентами и
локальными MDX-шаблонами. План развития включает переводы, регулярную работу с
блогом, Three.js и анимации. Поддержка старого генератора вместе с новым создала
бы два маршрутизатора, две модели контента и лишний клиентский runtime.

## Решение

Использовать Astro 7 как единственный движок сайта:

- статический HTML генерируется в `dist/`;
- Markdown и MDX загружаются Astro Content Layer из папки Obsidian;
- все текущие маршруты и alias проектов сохраняются;
- изображения из внешней папки контента обрабатываются Astro Assets;
- русская версия остаётся на URL без языкового префикса;
- схема контента заранее поддерживает `locale` и `translationKey`;
- общие компоненты реализованы на Astro, без React runtime;
- интерактивность подключается точечно нативными скриптами или островом на
  конкретной странице.

Старые конфигурации, шаблоны, страницы и зависимости Gatsby/React удалены. В
рабочем дереве не должно существовать параллельного legacy-контура.
Устаревший workflow автоматической публикации в GitHub Pages также удалён:
production-контур этого сайта — явно разрешаемая синхронизация `dist/` в S3.
`--delete-removed` очищает недоступные из новой сборки legacy-артефакты, поэтому
deploy считается destructive-операцией.

## Сохранённые контракты

- Публичные пути: `/`, `/notes/`, `/notes/<slug>/`, `/projects/<slug>/`, `/shop/`
  и существующие alias проектов.
- Источник контента: `OBSIDIAN_VAULT_PATH`.
- Статусы публикации: только `status: published` попадает на сайт.
- Google Analytics и Яндекс Метрика остаются в общем layout.
- Production-публикация остаётся отдельной явно разрешаемой операцией.

## Проверка

Перед публикацией обязательны:

1. `pnpm check` без ошибок и предупреждений.
2. `pnpm build` с генерацией всех ожидаемых страниц.
3. Проверка HTML, canonical, аналитики и отсутствия Gatsby/React в runtime.
4. Отдельная визуальная проверка desktop/mobile, если менялась вёрстка.
5. Только затем — явно разрешённый deploy и независимая проверка `shch.one`.

## Откат

Миграция откатывается только целиком через историю Git. Смешивать отдельные файлы
предыдущего движка с Astro нельзя. Сгенерированные `.cache/`, `public/` и `dist/`
не являются источником для отката.
